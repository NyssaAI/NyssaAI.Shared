# Adopt typescript standards locally

> [!IMPORTANT] Scope Directive
> Walkthrough for pinning and adopting the TypeScript development standards bundle within a consumer repository. It defines `.nyssa-ai/dev-standards/` directory placement, `AGENTS.md` linking, repository layout compatibility with `plan-product` and `compound-engineering`, and explicit checker execution; it does NOT wire CI automation, install global background hooks, or modify upstream projects.

This walkthrough activates standards through repository instructions and explicit local commands.
It adds no CI job, hook, skill or background execution. Installation alone does not activate rules.

## One-command adoption or update (`--sync`)

To adopt or update the pinned TypeScript standards bundle directly from your installed `dev-standards` plugin (or a local `dev-standards` checkout), run:

```text
python <plugin-root>/src/typescript/check_adoption.py . --sync
```

If `.nyssa-ai/dev-standards/typescript/scripts/check_adoption.py` is already present in the repository, you can also run:

```text
python .nyssa-ai/dev-standards/typescript/scripts/check_adoption.py . --sync
```

`--sync` deterministically populates `.nyssa-ai/dev-standards/typescript/` (removing any retired files from earlier versions), records the 40-character source revision in `.nyssa-ai/dev-standards/typescript.json` while preserving existing `source_roots` and `commands`, merges or updates the `# Development standards (typescript)` section in `AGENTS.md`, ensures `.gitignore` complies with `REPO-GITIGNORE`, and validates the resulting bundle.

## Pinned layout

Alternatively, choose an exact source commit and extract `dev-standards-typescript-0.6.3-source.tgz` into `.nyssa-ai/dev-standards/typescript` (for example, `tar -xzf dev-standards-typescript-0.6.3-source.tgz -C .nyssa-ai/dev-standards/typescript`). Do not copy `node_modules`, `.temp`, `bin`, `obj` or other build outputs. Keep the rulebooks (`repo-standards.md`, `architecture-standards.md` and `standards.md`), references, examples, scripts and lockfiles together. Do not link a user's plugin cache, which can disappear or change independently of this repository.

```text
repository/
  AGENTS.md
  CLAUDE.md -> AGENTS.md
  GEMINI.md -> AGENTS.md (or @./AGENTS.md)
  .nyssa-ai/
    dev-standards/
      typescript.json
      typescript/
        README.md
        rules/
        references/
        examples/
        scripts/
        adoption/
    plan-product/
  .compound-engineering/
  .temp/
  docs/
  src/
  test/
    unit/
    use_case/
```

Copy [repository.example.json](repository.example.json) to `.nyssa-ai/dev-standards/typescript.json` (or review the file generated by `--sync`).
Replace the revision marker with the exact 40-character source Git commit or bundle digest, set all owned source
roots, and adapt the command arrays and working directories to the actual repository. In a
monorepo, list each TypeScript app or tool source root, such as
`apps/sales-researcher/src` and `tools/crm/src`; the checker applies the pinned structural rules to
every listed root. The repository-level manifest is a prerequisite for TypeScript CI enumeration:
until `.nyssa-ai/dev-standards/typescript.json` exists with those roots, do not claim that a
monorepo CI check covers every TypeScript project. These are examples, not guessed universal test
commands. Commands are argument arrays, run without a shell; do not put `&&`, redirects or shell
expressions in them. Each working directory is relative to the repository root.

Merge [AGENTS.fragment.md](AGENTS.fragment.md) into the root `AGENTS.md` (with `CLAUDE.md` symlinked
to `AGENTS.md`, `GEMINI.md` symlinked or importing `@./AGENTS.md` when used, and no diverging `.hermes.md`,
`HERMES.md`, or `AGENTS.override.md` overrides); preserve existing instructions. Ensure `.gitignore` ignores
`.temp/`, `.worktrees/`, `.compound-engineering/*.local.yaml`, `.context/compound-engineering/`, and
`.nyssa-ai/plan-product/usage/`, while keeping `.nyssa-ai/dev-standards/`, `.nyssa-ai/plan-product/`,
`.compound-engineering/config.yaml`, and `docs/` tracked in Git (`REPO-GITIGNORE`). The fragment's paths
describe the layout above. Review the resulting instructions and command definitions before running them.

Install the copied bundle's locked checker dependency with `npm ci --ignore-scripts` from its directory. The target repository installs its own dependencies separately.

## Verify the wiring, then run locally

From the consuming repository root:

```text
python .nyssa-ai/dev-standards/typescript/scripts/check_adoption.py .
python .nyssa-ai/dev-standards/typescript/scripts/check_adoption.py . --run
python .nyssa-ai/dev-standards/typescript/scripts/check_adoption.py . --run --use-case
```

The first command checks the pin's format, copied support files, instruction reference, repository
organization invariants (no ad-hoc `tmp`/`temp`/`scratch` folders, no competing `tests`/`__tests__`
roots, no catch-all folders, and no co-mingled test files inside `source_roots`), command working
directories and executable availability. It does not run builds or tests, or claim that the recorded
revision authenticates the copied bytes. Review the copy against its source revision when adopting
or updating it.

`--run` executes the configured build and unit commands and checks each owned source root.
`--run --use-case` also executes the configured use-case suite; its fixtures own Docker resources.
A failed command is nonzero. Unsupported checker surfaces remain visible and nonzero; assess them
with source review and compiler/test evidence rather than rewriting valid code merely to satisfy
the checker. There is no exception registry or mandatory CI gate.

Run the relevant commands after changes and record what passed, failed or remained blocked.
Run the bundle's own example commands from its README separately; passing sample tests does not
verify the consuming application. Update the pinned bundle and recorded revision together and
review rule changes before accepting an update.
